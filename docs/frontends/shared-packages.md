# Shared TypeScript Packages

The Expo mobile and web surfaces share `@mitsuro/api`, `@mitsuro/state`, and
`@mitsuro/ui` through the Bun workspace. These packages live under `packages/`
and resolve locally without a package registry publication.

Native Canvas is a Rust desktop client using `mitsuro-client` and shared server
contracts. It does not consume the abandoned React/Tauri desktop application.
Shared business logic remains in core/server; TypeScript packages implement
mobile/web client state and presentation.

## The API Package

`@mitsuro/api` is the TypeScript client that talks to the Mitsuro server's REST API. It exports a single class, `MitsuroClient`, along with every TypeScript type used in the request/response cycle.

### MitsuroClient

You create a client by passing a configuration object with the server's base URL and an optional bearer token:

```ts
import { MitsuroClient } from '@mitsuro/api';

const client = new MitsuroClient({
  baseUrl: 'http://localhost:3000',
  token: 'your-auth-token',
});
```

The constructor also accepts a `fetchImpl` parameter for environments where the global `fetch` does not support streaming (React Native, for example). This lets the mobile app swap in a compatible fetch implementation without changing any of the client's internal logic.

Every method calls a private `request()` helper that prepends `/api` to the path, attaches auth headers, and parses error responses. The API surface covers every domain the frontends need:

- **Sessions** -- create, list, update, delete, and load sessions with their full message history.
- **Chat streaming** -- send messages via server-sent events. The `streamChat()` method accepts a `StreamCallbacks` object with handlers for text deltas, thinking deltas, tool calls, plan updates, usage stats, and completion events. The stream includes a 30-second inactivity timeout that fires an error if the server goes silent.
- **Git** -- fetch repository status, list branches and worktrees, and check out branches.
- **Credentials and OAuth** -- manage provider API keys and walk through OAuth flows for providers that support them.
- **Files** -- browse directory trees and read individual files.
- **MCP** -- list, connect, disconnect, and inspect tools from MCP (Model Context Protocol) servers.
- **Hive** -- dispatch autonomous agent tasks, list running sessions, send messages, pause, resume, cancel, and observe live events from Hive sessions.
- **Presence** -- heartbeat and track which clients are viewing or controlling a session.
- **Reports** -- retrieve summaries and full reports generated by Mitsuro sessions.
- **Preview/Ports** -- discover running services, manage pinned and hidden ports, and control preview settings.

### Types

The `types.ts` file is the canonical source for every interface the server can return or the client can send. This includes session responses, message content blocks (text, tool use, tool result, thinking), chat requests with optional image attachments, git structures, model metadata, stream event discriminated unions, and the full set of Hive autonomous agent types. Both apps import these types directly rather than defining their own.

### Thinking Helpers

The package also exports a small set of thinking-related utilities in `thinking.ts`. These handle cycling through thinking levels (off, low, medium, high, max), converting levels to API values, and generating display labels. The cycling logic is model-aware: Codex and Opus 4.6 models get the full five-level cycle, while other models toggle between off and medium.

## The State Package

`@mitsuro/state` provides Zustand-based stores that manage all client-side state. Zustand is a minimal state management library for React -- each store is a hook that components subscribe to, and updates trigger re-renders only in components that read the changed slice. The package depends on `@mitsuro/api` for its client class and types, and declares Zustand as a peer dependency so the consuming app controls the version.

### Storage Abstraction

The package defines a `MitsuroStorage` interface with three methods: `get`, `set`, and `delete`. This is a simple key-value contract that mirrors `localStorage`. A `MemoryStorage` implementation ships for testing. The mobile app provides its own implementation backed by `expo-secure-store` on native and `localStorage` on web. This abstraction lets stores persist state across app restarts without coupling to any platform-specific API.

### Session Store

The session store (`createSessionStore`) is the largest store in the package. It manages the active chat session's full lifecycle: loading messages from the server, sending new messages, handling streaming responses via SSE, tracking tool call state (pending, running, success, error, awaiting approval), managing thinking content, handling message queuing during active streams, and polling for session state changes. It also manages presence heartbeats so the server knows which clients are watching a session, and it coordinates with the plan store to display task progress during plan mode.

The store tracks mode (build or plan), permission mode (supervised or autonomous), thinking level, model selection, token counts, and error state. It also includes Fast-mode logic that preserves the selected model and uses the model catalog's provider-specific Fast contract when one is advertised.

### Sessions Store

The sessions store (`createSessionsStore`) manages the list of all sessions. It handles loading the session list from the server, creating new sessions with optional working directories and target branches, deleting sessions, and selecting a session (which updates the workspace store to reflect the selected session's directory). It coordinates with the workspace store so that navigating between sessions also updates the active project directory.

### Workspace Store

The workspace store (`createWorkspaceStore`) tracks the current working directory, workspace mode (neutral, selected, or created), and the active session ID. It persists this state to the storage abstraction so the app can restore the user's last workspace on launch. The mode distinguishes between sessions with no directory (neutral), sessions where the user picked an existing directory (selected), and sessions where Mitsuro created a new workspace (created).

### Git Store

The git store (`createGitStore`) manages repository state for the current workspace. It fetches git status (branch, staged/modified/untracked counts, ahead/behind), branch lists, and worktree lists from the server. It supports branch checkout, worktree switching (which also updates the workspace directory), and automatic background polling every five seconds to keep the UI current as the repository changes.

### Plan Store

The plan store (`createPlanStore`) manages the task list that appears during plan mode. It holds an array of plan items (each with an ID, content string, and completion flag) and a visibility toggle. The session store feeds plan updates from the stream into this store so the UI can render a live checklist of tasks as the AI works through them.

## The UI Package

`@mitsuro/ui` defines the visual language shared across platforms. It exports design tokens and a theme system rather than React components, since mobile and desktop have different component libraries (React Native versus DOM).

### Design Tokens

The `tokens.ts` file defines every low-level value in the design system:

- **Colors** -- a dark-mode palette inspired by iOS Liquid Glass, plus light-mode overrides. Includes core colors, message colors (user blue, AI subtle, thinking amber), status colors, surface colors, and glass-effect values with configurable blur intensity.
- **Spacing** -- a scale from 2px (`xxs`) to 48px (`xxxl`) used for padding, margins, and gaps.
- **Radii** -- border radius values from 4px (`xs`) to 999px (`pill`).
- **Font sizes** -- a typographic scale from 11px (`xs`) to 34px (`hero`).
- **Font weights** -- regular (400), medium (500), semibold (600), bold (700).
- **Fonts** -- system sans-serif by default, JetBrains Mono for code.
- **Shadows** -- small, medium, and large presets using React Native's shadow properties, plus a `glow` factory function for colored halos.
- **Animation** -- timing values (150ms fast, 250ms normal, 400ms slow) and spring physics parameters for gesture-driven animations.

### Theme

The `theme.ts` file builds on the tokens to create complete theme objects. The `createTheme()` function takes a resolved color scheme (dark or light) and returns a `Theme` object that maps semantic color names to the correct token values for that scheme. Two pre-built themes are exported: `darkTheme` and `lightTheme`. Components consume these themes through a React context so that switching between dark and light mode updates the entire UI in one pass.

## How They Are Consumed

Both apps declare the shared packages as workspace dependencies using Bun's `workspace:*` protocol. In the mobile app's `package.json`, for example, the hooks and components import directly from the package names:

```ts
import { MitsuroClient } from '@mitsuro/api';
import { createSessionStore, createWorkspaceStore } from '@mitsuro/state';
import { createTheme, type ColorScheme } from '@mitsuro/ui';
```

Bun resolves these imports to the local `packages/` directories at install time. There is no build step for the packages -- each package's `main` and `types` fields point directly at `src/index.ts`, so the consuming app's bundler (Metro for mobile, Vite for desktop) handles TypeScript compilation. Edit a file in `packages/api/src/` and the change is immediately reflected in whichever app you are running.

## Package Manager

The monorepo uses Bun as its package manager and runtime. Bun's workspace support links the `@mitsuro/*` packages without publishing, and its speed makes installs and script execution noticeably faster than npm or yarn.
